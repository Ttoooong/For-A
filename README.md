# For-A

A 股信息监控平台 —— 多源行情与公告采集、规则引擎驱动告警。

零成本起步：免费公开接口即可覆盖盘中秒级行情、历史行情、上市公司公告三类数据；
多源交叉校验保证拿到的数字可信；规则引擎把异动、涨跌停、放量、公告事件变成可推送的告警。

---

## 快速开始

```bash
pip install -r requirements.txt

# 1) 自检各数据源连通性
python -m for_a check

# 2) 拉一次行情快照
python -m for_a quote --codes 600519,000001,300750,688981

# 3) 查某只股票的公告
python -m for_a announcements --code 600519 --limit 10

# 4) 常驻监控
cp config.example.yaml config.yaml   # 按需修改 watchlist / 规则阈值 / 告警通道
python -m for_a watch --config config.yaml
```

安装为命令行工具：

```bash
pip install -e .
for-a watch --config config.yaml
```

## 架构

```
数据源                聚合               规则引擎              告警出口
─────────────      ────────────      ──────────────      ─────────────
腾讯 qt.gtimg.cn  ┐                 涨跌幅超阈值   ┐
新浪 hq.sinajs.cn ┤→ 多源交叉校验  → 触及涨跌停    ├→ 告警去重  →  控制台
东财 push2        ┘  （分歧告警）    换手率/放量    │   （SQLite）   飞书
巨潮 cninfo         主源 + 校验源    公告关键词命中 ┘                钉钉 / 企业微信
                                                                   通用 Webhook
```

| 模块 | 说明 |
|---|---|
| `for_a/sources/` | 各数据源适配器，输出统一到 `Quote` / `Announcement` |
| `for_a/aggregator.py` | 主源 + 校验源交叉比对，计算价格分歧度、识别卡住的源并降级 |
| `for_a/rules/` | 规则实现，价格类规则基于行情、公告类规则基于标题关键词 |
| `for_a/alerts/` | 告警出口，控制台 / 飞书 / 钉钉 / 企业微信 |
| `for_a/storage.py` | SQLite：告警去重、规则状态机、上次行情快照、已读公告 |
| `for_a/watch.py` | 监控主循环，单轮失败不终止整体 |

### 告警节奏：阈值穿越，不是数值快照

规则不会在每次轮询时重复推送同一条异动，而是维护一个状态：

| 规则 | 推送时机 |
|---|---|
| 涨跌幅 | **穿越**阈值时推一条（继续上涨不再推；跌回阈值以下后再次涨破才重推） |
| 涨跌停 | 封板时推一条（开板后再次封板才重推） |
| 换手率 | 每 **5%** 一档提醒（换手率一路走高时分档推送） |
| 放量 | 每个 **5 分钟窗口**内最多一条 |
| 多源分歧 | 同一标的 **15 分钟**内最多一条 |
| 主源卡住 | 卡住时推一条，恢复后允许再次推送 |
| 公告关键词 | 按公告号，每条公告只推一次 |

状态存在 SQLite 的 `rule_states` 表里，进程重启后依然有效。

## 数据可靠性：七道闸门

免费公开接口没有 SLA，这七条是本项目在工程上做的硬约束：

1. **复权口径必须显式声明** —— 东财 `push2his` 的 `fqt=1`（前复权）在远端会算出负价，长周期回测用 `fqt=2` 后复权。
2. **多源交叉校验** —— 主源与校验源价格分歧超阈值（默认 0.5%）即触发 `divergence` 告警，分歧时以有授权的源为准。
3. **限流与退避** —— 同域名最小请求间隔默认 0.5s（**按 host 分桶**，不同镜像互不阻塞）；东财 push2his 连续重试会被限流，超限常返回空值而非报错，因此每层都做重试与镜像降级。
4. **不要假设"刚拿到就是新的"** —— 用行情自带的时间戳字段自检新鲜度；聚合器会比对各源时间戳，**识别卡住的源**。主源卡住时自动降级到时间最新的源，并**跳过该标的价格类规则**——不在过期数据上做决策。
5. **免费源不能当唯一源** —— 主源失败时聚合器自动回退到校验源，单源故障不会让整条链路挂掉。
6. **响应必须自校验** —— 免费镜像在高频访问下会返回**字段值错位**或全空的报文。代码校验「返回代码 == 请求代码」且「最新价 > 0」，不通过的报文直接丢弃并换下一个镜像，绝不写进基线。
7. **盘口深度是授权不是功能** —— 免费公开接口只到五档，十档/逐笔需 Level-2。

### 实测得出的数据源事实

这些结论来自 2026-11-27 盘中实测，写下来是为了避免以后按旧资料"纠正"代码：

| 事实 | 说明 |
|---|---|
| **ST / \*ST 主板股票涨跌停是 10%，不是 5%** | 实测 `000010 *ST美丽` 昨收 0.86 / 涨停 0.95、`000056 *ST皇庭` 昨收 1.74 / 涨停 1.91。`guess_limit_pct` 的 10 / 20 / 30 假设与现行规则一致 |
| 创业板 / 科创板 20%，北交所 30% | 实测 `300750` +20.00%、`688981` +20.00%、`920799` 昨收 22.70 / 涨停 29.51 |
| 东财 `ulist.np` 批量端点不可用 | 实测会返回字段值严重错位的报文（`f43=230947.61`、`f57=11.9015685357`），不能用它做批量。改用 4 镜像并发分片 |
| 东财逐代码串行是性能瓶颈 | 串行实现要发 N 次请求，墙钟随自选股数量线性增长（50 只自选股约需 14s，吃光 15s 轮询预算）。改为 4 镜像并发分片后，每个镜像只负责 1/4 的代码。腾讯 / 新浪一次请求就能拿全部代码（0.16s / 0.05s），本项目保留东财作为校验源 |
| 腾讯 / 新浪的字段下标稳定 | 三源对昨收、今开、最高、最低完全一致 |

## 配置

`config.example.yaml` 是完整示例，常见字段：

```yaml
watchlist: ["600519", "000001"]

sources:
  primary: eastmoney        # 主源
  verify: [tencent, sina]   # 校验源
  min_interval: 0.5         # 同域名最小请求间隔（秒）
  divergence_tolerance: 0.005

rules:
  price_change: { enabled: true, threshold_pct: 5.0 }
  limit:       { enabled: true }
  turnover:    { enabled: true, threshold_pct: 10.0 }
  volume_surge:{ enabled: true, ratio: 3.0 }
  announcement:
    enabled: true
    keywords: [重组, 停牌, 立案, 问询函, 减持, 质押]

poll:
  interval_seconds: 15
  announcement_interval_seconds: 300

alerts:
  - type: console
  - type: webhook
    webhook:
      type: lark              # lark | dingtalk | wecom | generic
      env_url: FORA_LARK_WEBHOOK_URL
      env_secret: FORA_LARK_SIGN_SECRET
```

> YAML 会把 `000001` 解析成整数 `1`，**自选股代码务必加引号**。配置层会按 6 位补零还原
> （`000001` → `000001.SZ`），但加引号更直观。

Webhook 的地址与密钥走环境变量（见 `.env.example`），不要写进仓库。`env_url` /
`env_secret` 指向的环境变量**优先于**配置文件里的 `url` / `secret`。

## 扩展

**加一个行情源**：继承 `for_a/sources/base.py` 的 `QuoteSource`，实现 `fetch(codes) -> dict[str, Quote]`，
在 `for_a/sources/__init__.py` 的注册表里登记。

**加一条规则**：继承 `Rule`（行情类）或 `AnnouncementRule`（公告类），实现 `evaluate`，
在 `for_a/rules/__init__.py` 的 `build_rules` 中加入。

需要「一次异动只推一条」这类语义时，继承 `rules/price.py` 里的 `_StatefulRule`，
实现 `current_state` 返回状态字符串——基类会负责比较新旧状态并决定要不要推送。

**加一个告警出口**：继承 `Alerter`，实现 `send(alerts)`，在 `for_a/alerts/__init__.py` 登记。
